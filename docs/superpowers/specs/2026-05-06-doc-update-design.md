# 工程文档同步更新设计

**日期**: 2026-05-06
**目标**: 将 4 个 md 工程文档与当前代码状态对齐，建立"持续优化"指引

## 一、问题分析

| 文件 | 主要问题 |
|------|---------|
| README.md | 项目结构缺少 `TpmsBroadcastParser.kt`、`VehicleTopView.kt`、`BleConnectionState.kt`；功能列表未提及广播解析、设备映射 |
| CLAUDE.md | 当前进度停留在 2026-03-15，后续多项工作未记录 |
| DEVELOPMENT_REPORT.md | 2026-04-07 报告；提交历史只到 4 月，缺 6 次后续提交；文件清单和"待完成事项"严重过时 |
| TODO.md | RSSI 显示、应用图标等已完成项未标记 |

## 二、方案

**方案 B**：精简合并 + 精确修复

- 保留 4 个文件，但精简内容、去除易过期明细
- 共同遵循"职责单一"：README 面向用户、CLAUDE.md 面向开发/AI、DEVELOPMENT_REPORT.md 记录里程碑、TODO.md 跟踪待办

## 三、各文档设计

### 3.1 README.md（面向用户/新协作者）

**包含**：
- 项目简介、功能列表（更新为当前实现）
- 技术栈（强调广播数据解析方式）
- 开发环境要求
- 完整项目结构（包含所有现有文件）
- **运行项目**章节（编译、安装、注意事项）
- **持续优化**章节（P0~P3 优先级表）

**移除**：
- `push.bat` 使用说明（与文档主题无关）

### 3.2 CLAUDE.md（面向开发/AI 上下文）

**保留**：项目概述、环境配置、项目结构骨架

**更新**：
- 当前进度日期更新为 2026-05-06
- 已完成项更新为完整列表（含 BLE 解析、设备映射、车辆俯视图等）
- 下一步聚焦真机测试、报警实现、历史记录

### 3.3 DEVELOPMENT_REPORT.md（项目里程碑摘要）

**保留**：项目概述、系统架构、关键设计决策、状态管理定义、注意事项

**改造**：
- 删除 30+ 行逐文件清单（与 README 项目结构重复，易过期）
- 删除完整 commit 历史（用 `git log` 替代）
- 添加"开发里程碑时间线"章节（按月份记录关键节点）
- 更新"待完成事项"按 P0~P3 优先级（与 TODO.md 对齐）

### 3.4 TODO.md（待办跟踪）

**改造**：
- 按 P0（真机验证）/P1（核心功能增强）/P2（用户体验）/P3（长期优化）优先级分类
- 已完成项独立分区（保留勾选记录）
- 移除已无意义的 TODO（如"添加应用图标"已实现）
- 新增基于当前代码状态的具体任务（如阈值配置、报警弹窗）

## 四、实施步骤

1. 更新 README.md
2. 更新 CLAUDE.md
3. 更新 DEVELOPMENT_REPORT.md
4. 更新 TODO.md
5. 验证项目仍可编译（防止意外改到代码）
6. Git 提交并推送

## 五、不在范围

- 不重构代码或调整包结构
- 不新增功能（如报警、历史图表）—— 由 TODO.md 中的 P1+ 任务跟踪
- 不修改 `keystore.jks`、`gradle.properties` 等配置
